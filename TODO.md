- [x] **Thunder was the soundscape worklet's most expensive layer while it pealed.** `renderThunder` (`apps/notes/public/soundscape-generator.js`) now renders rumble-major: the block is cut at each peal start, each peal's rolls are stepped into scratch, each rumble runs its stretch in one loop with its three filters' state in locals (`renderPealSegment`), and the mix, contrast and output high-pass follow in one pass. Two overlapping peals went from 32% to 13% of real time at 48 kHz in the vitest harness, and the output is **bit-identical** to the sample-major walk (10.2M samples compared across two sample rates, an odd block size, full contrast both ways, and peal removal -- which is why spent peals are swapped out in the order the walk would have removed them, and why a sample with no peal present still skips the contrast follower and the high-pass). ## Found investigating "reopening a large external file freezes the app"

- [x] **Render view, every reopen: a 3-4s main-thread freeze.** The pane showed its scroller before it mounted the block window, and the window's adjustment passes, running against that scroller with no window to measure, grew the range by a screenful of blocks per pass until it covered the whole document. The whole document was then rendered in one commit: ~22,000 nodes laid out synchronously. A pass now declines while no window is mounted, and the window's arrival runs the first real pass (`usePreviewWindow.tsx`, `containerEl`). The gate is `apps/notes/scripts/perf/verifyExternalReopenWindow.mjs`, which fails without the fix. Edit mode was never affected.
- [x] **Typing retained one copy of the document per keystroke, permanently** (+267 MB after 120 characters on a 2 MB note). Chains of stale render scopes kept every old copy: memoized callbacks keep the scope they were created in, and every scope held the text because it was React state passed down as a string. The text now lives in one store per section, read through `readEditorText()` and keyed on `editorTextVersion`. Kept derived strings are detached. Note summaries no longer carry content. See `docs/editor-input-pipeline-plan.md`, "What a keystroke may retain". The gate is `apps/notes/scripts/perf/measureTypingRetention.mjs` (0.13 MB per cycle of 20 keystrokes and a save, down from ~44 MB).
- [ ] **Superseded block-map prewarms are still parsed.** Each typing pause schedules a full split of the new text (`useEditorSectionMount`'s background prewarm). The worker answers requests one at a time, and nothing withdraws a request that a newer text has made pointless. On a large note, typing with pauses shorter than one parse therefore builds a queue. Each queued request holds a copy of its text (`documentFactsClient.ts`'s `inFlightByText`) until the worker reaches it, and its answer is then discarded. This is bounded by idle time, so it is not a leak, but it wastes CPU and memory in proportion to typing. Fix: keep at most one prewarm request queued behind the running one, replacing it rather than appending.
- [x] **A save sent the whole note back over IPC.** `saveNote` now returns a summary without content (`noteLifecycleService.ts`'s `withoutContent`, and the browser mock alike); the renderer puts the text it saved into the note-content store itself (`withSavedNote`), and App's `setNotes` keeps the previous list when only content changed (`keepIfUnchanged`), so a save still does not re-render the list. The store therefore holds the editor's text, not the database's sanitized copy -- the same on every path that types, since typing produces clean text.
- [ ] **`saveNote` still reads the whole file back after writing it.** `readSummary` re-reads the note (`fs.readFile`, or the stored content for a temp note) to build the summary it returns -- a second pass over a note the call just wrote. The summary's fields could be computed from the text in hand. Main-process only; no longer crosses IPC.
- [x] **Importing a 2 MB external note cost ~400 ms of synchronous main-process work.** Note text now lives in a plain `note_content` table keyed by note id; the FTS5 index was never searched. The import writes the text once (~585 → ~330 ms for import+close with 300 notes).
- [x] **Each open of an external note hashed its whole text with SHA-256.** Nothing read the hash. It is removed, and activation fetches only the from-disk baseline (`notes:get-from-disk-baseline`).
- [ ] **Two render-view regression scripts fail on `main` before and after this change, identically:** `verifyScrollBridge.mjs` ("a short journey does not raise one / stretch the thumb") and `verifyModeToggleRoundTrip.mjs` (a 13-block drift, the known item above). A third `verifyScrollBridge` check ("thumb holds still, stretched") fails intermittently. Separately, in cloud containers the scripts that launch Playwright's default browser fail before running, because the installed Playwright expects a newer headless-shell build than the container ships. Point `PLAYWRIGHT_BROWSERS_PATH` at a directory holding a `chromium_headless_shell-<expected>` symlink to the installed one.

- [x] **Mobile schedule: assign by MARKING a soundscape.** Built as PICKING UP: a long press on a soundscape picks it up without playing it, and every slot tap fills a slot with it until a tap on it puts it down (`SoundscapeControls`' `onPickPreset`, `ScheduleGrid.tsx`).
