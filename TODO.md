## Split-view rough edges (carried over from split-view handover doc)
- [x] `editorStageRef` (App.tsx) was one shared ref across all sections for the background-texture-sizing `ResizeObserver`. Deleted rather than made per-section: every texture is one repeating 512px tile (`useTextureSurface` always generated at `TEXTURE_REPEAT_TILE_SIZE`; the stylesheets repeat it), so the sizes that observer measured -- app grid, sidebar and stage -- were never read, and all it did was re-render `App` during a window resize. The hook no longer takes a size.
- [x] `pendingViewportRestoreRef`/`isApplyingInitialViewportRef` were shared across sections. Deleted rather than split: their only writer was `seedInitialViewport`, which nothing called, so both were permanently null/false and every branch reading them was unreachable -- including the guard in `queueAppStateSave` and the pending-restore branch of `onViewportChange`.
- [x] **Thunder was the soundscape worklet's most expensive layer while it pealed.** `renderThunder` (`apps/notes/public/soundscape-generator.js`) now renders rumble-major: the block is cut at each peal start, each peal's rolls are stepped into scratch, each rumble runs its stretch in one loop with its three filters' state in locals (`renderPealSegment`), and the mix, contrast and output high-pass follow in one pass. Two overlapping peals went from 32% to 13% of real time at 48 kHz in the vitest harness, and the output is **bit-identical** to the sample-major walk (10.2M samples compared across two sample rates, an odd block size, full contrast both ways, and peal removal -- which is why spent peals are swapped out in the order the walk would have removed them, and why a sample with no peal present still skips the contrast follower and the high-pass). What remains is the layer's real arithmetic plus the contrast's per-sample `pow`; cutting either would change samples.

- [x] **Regression scripts failed intermittently: the harness leaked dev servers.** `perfHarness.mjs` started Vite through `npm run` in a shell, so on Windows the server sat at the end of a wrapper chain (cmd, npm, cmd, Vite) that `taskkill /T` on the outer shell did not end -- and `stop()` fired that kill without waiting, so a script exiting straight after could take the kill with it. A surviving server held its port, and the next script on that port waited only for SOMETHING to answer there, so it ran against the stale server (old code) while its own Vite exited on `--strictPort` unnoticed. That was `verifyEditRowGrid`'s missing `.cm-scroller` and `verifyTagBarSuggestionFit`'s missing bridge: a page that stopped being the app. Vite is now spawned directly (Node running `vite/bin/vite.js`), so the process held IS the server and `stop()` ends it on every platform, and readiness waits for that process to announce its own port. Several scripts still share a port, which only matters if two run at once -- and that now fails loudly.
- [x] **A large note's render-view scrollbar thumb froze at its first instalment's size.** `isThumbRatioSettled` answered true from the first answer, and the scrollbar commits the thumb's size on the first settled answer, keyed on the full text's length -- so a ratio taken over the blocks delivered so far was held for good (20px where 10px was right on a 400,000-character note). It is settled once the split is complete. `verifyPreviewCharThumb` found it once its setup was fixed.

- [x] **Learn the wheel's notch size only from deltas that look like notches** (`apps/notes/src/scroll/wheelNotch.ts`). The unit used to be the smallest delta ever seen, so one fast trackpad swipe taught a small notch and every later mouse-wheel click scrolled several rows and turned the escape ring several cells. ## Found investigating "reopening a large external file freezes the app"

- [x] **Render view, every reopen: a 3-4s main-thread freeze.** The pane showed its scroller before it mounted the block window, and the window's adjustment passes, running against that scroller with no window to measure, grew the range by a screenful of blocks per pass until it covered the whole document. The whole document was then rendered in one commit: ~22,000 nodes laid out synchronously. A pass now declines while no window is mounted, and the window's arrival runs the first real pass (`usePreviewWindow.tsx`, `containerEl`). The gate is `apps/notes/scripts/perf/verifyExternalReopenWindow.mjs`, which fails without the fix. Edit mode was never affected.
- [x] **Typing retained one copy of the document per keystroke, permanently** (+267 MB after 120 characters on a 2 MB note). Chains of stale render scopes kept every old copy: memoized callbacks keep the scope they were created in, and every scope held the text because it was React state passed down as a string. The text now lives in one store per section, read through `readEditorText()` and keyed on `editorTextVersion`. Kept derived strings are detached. Note summaries no longer carry content. See `docs/editor-input-pipeline-plan.md`, "What a keystroke may retain". The gate is `apps/notes/scripts/perf/measureTypingRetention.mjs` (0.13 MB per cycle of 20 keystrokes and a save, down from ~44 MB).
- [x] **A save sent the whole note back over IPC.** `saveNote` now returns a summary without content (`noteLifecycleService.ts`'s `withoutContent`, and the browser mock alike); the renderer puts the text it saved into the note-content store itself (`withSavedNote`), and App's `setNotes` keeps the previous list when only content changed (`keepIfUnchanged`), so a save still does not re-render the list. The store therefore holds the editor's text, not the database's sanitized copy -- the same on every path that types, since typing produces clean text.
- [x] **Importing a 2 MB external note cost ~400 ms of synchronous main-process work.** Note text now lives in a plain `note_content` table keyed by note id; the FTS5 index was never searched. The import writes the text once (~585 → ~330 ms for import+close with 300 notes).
- [x] **Each open of an external note hashed its whole text with SHA-256.** Nothing read the hash. It is removed, and activation fetches only the from-disk baseline (`notes:get-from-disk-baseline`).
- [x] **Render-view regression scripts failed in setup** (`verifyScrollBridge`, `verifyModeToggleRoundTrip`): after a reload the slot mounts in edit view and App's state restore switches it to the persisted mode afterwards, so `ensureEditMode` looked too early, pressed nothing, and then watched the restore hide the editor. `perfHarness.mjs`'s `reloadInMode` now hands the wanted mode across the reload (an init script writes it into the mock's store, since the page's own `beforeunload` save would overwrite a write made before). Both scripts pass. `verifyTagBarSuggestionFit`'s squeeze check failed because its fixed 420px squeeze stopped being one after the tag bar's layout changed (12px off a row with 22px of slack); the squeeze is now derived from the measured slack. The product behaviour was fine.
